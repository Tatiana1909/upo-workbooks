# Изменения для согласования

Ветка: feature/editable-upo-editions-20261026. Изменения не развёртываются на рабочем порту 8081 из этой ветки.

- Импорт двух исходных тетрадей в полные редактируемые черновики. Импорт идемпотентен, не читает и не обновляет учебные результаты. Нельзя повторным импортом затереть правки преподавателя.
- По 7 игр; 15 и 21 контрольный вопрос; все практические действия, заметки, вводные карточки, теория, правила, памятки и ссылки из актуальных источников.
- Редактируемые тип материала, название, URL, отдельная ссылка скачивания; стиль текста, продолжительность, подпись завершения, баллы практики и скриншоты.
- Неизменяемые публикации существующего механизма; история версий; отображение версии участнику. Ключи новых версий скрыты публичным API; ответы проверяются на сервере.
- Отдельный аутентифицированный предпросмотр черновика по ссылке.
- Копия рисунка игры имеет адрес по SHA-256, поэтому старые публикации сохраняют прежнее изображение.
- Полный защищённый резервный архив: SQLite online backup, изображения и доказательства, конфигурация, ключи и код. Проверяются хеши и восстановление SQLite в отдельный временный файл. Рабочие архивы не публикуются в GitHub.

## Объединение с пожарной тетрадью

Общие файлы: server/builder.py, server/Dockerfile, v4/builder/{editor,render,workbook,catalog}.js, v4/builder-v4.css. Для пожарного курса нельзя использовать обычный импорт, ослаблять current_admin/current_user или заменять специальный экзамен обычными тестовыми блоками. Пожарные сеансы по-прежнему не имеют доступа к складскому конструктору. Требуется отдельное расширение с ограниченной областью и сохранением специального движка. Старые fire.py/fire.js/data.json не изменяются.

## Восстановление

Серверный архив хранится с правами 0600 в каталоге 0700. При восстановлении сначала проверяют SHA256SUMS. В новый отдельный том извлекают data/workbooks.sqlite3 и все data/* из data-and-image.tgz; в отдельную директорию восстанавливают исходники и server/.env из deployed-source-and-settings.tgz. Восстанавливают образ/настройки по container-settings.json, проверяют PRAGMA integrity_check и контрольные суммы, запускают отдельный контейнер и проверяют ссылки и вложения. Только после проверки возможна замена рабочего контейнера. Экспериментальное восстановление поверх рабочего тома запрещено.
