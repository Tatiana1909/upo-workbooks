# Персональные аккаунты и реестр участников

Реестр открывается через «Администрирование → Управление участниками», из меню общего кабинета и по ссылке «Участники» в кабинете пожарной безопасности. Одна карточка действует для всех направлений. Организация не запрашивается.

## Первый запуск

Перед обновлением создать и проверить полную резервную копию данных, материалов, исходников и настроек. Выполнить проверку сначала на отдельной копии базы. Рабочее подключение с передачей паролей должно использовать HTTPS.

При первом запуске создаётся один персональный администратор с логином и начальным паролем из существующей серверной конфигурации WORKBOOK_ADMIN_LOGIN и WORKBOOK_ADMIN_PASSWORD. Первый вход — `/v4/accounts.html`. До смены первоначального пароля доступен только профиль. После смены значения из конфигурации больше не заменяют персональный пароль при перезапусках.

Администратор добавляет подразделения, создаёт отдельных преподавателей, назначает им направления, разрешённые действия и подразделения. Участники могут создаваться вручную, из Excel/CSV или самостоятельно по приглашению. Каждому выдаётся уникальный логин.

## Создание и регистрация

Обязательны фамилия, имя, отчество либо отметка об отсутствии, подразделение, табельный номер либо отметка об отсутствии. Должность обязательна при самостоятельной регистрации; при создании ответственным или загрузке её можно внести позже. Табельный номер необязателен и хранится как текст, включая начальные нули. Он уникален в пределах единой организации. Существующие совпадения ФИО и подразделения требуют проверки ответственным; тёзку можно создать отдельно с явным подтверждением.

При ручном создании и загрузке выдаётся временный пароль, показанный однократно. При входе требуется сменить его. При самостоятельной регистрации участник вводит и подтверждает собственный пароль сразу; после регистрации сохраняет автоматически созданный логин.

Приглашение содержит назначенные курсы, необязательное фиксированное подразделение, название группы, срок 1–90 дней и лимит регистраций. Код виден один раз; используется в ссылке `accounts.html?invite=...`. Приглашение можно отозвать. Данные регистрации и использованного приглашения фиксируются в журнале; паролей в журнале нет. Саморегистрация всегда создаёт только участника, независимо от присланных дополнительных полей.

Для Excel/CSV: Фамилия, Имя, Отчество, Подразделение, Должность, Табельный номер. CSV — UTF-8, разделитель `;`; XLSX — первый лист. Не более 1000 записей и 5 МБ. Сначала предпросмотр, затем подтверждение корректных строк. Повторная серверная проверка выполняется при сохранении; конфликт откатывает всю подтверждаемую группу. Доступы после массового создания показаны однократно.

## Права

Участник видит собственные результаты назначенных ему версий. Новая версия назначается отдельно: её результаты не смешиваются с предыдущей.

Преподаватель имеет персональный аккаунт. Администратор выбирает направления УПО/ПБ, разрешения просмотра, проверки, редактирования и публикации, а также подразделения. Преподаватель видит участников своих подразделений либо созданных по его приглашению. Исторические записи без персонального аккаунта доступны администратору и автоматически не связываются с новым реестром.

Для автора всего направления список курсов в карточке преподавателя оставляют пустым. Если заданы конкретные версии, разрешён просмотр и проверка назначенных курсов, а общий конструктор закрыт: без привязки черновиков к отдельным версиям доступ к нему мог бы раскрыть другие тетради. Это ограничение явно сообщается пользователю.

Доступ к результатам, скриншотам и выгрузкам проверяется на сервере. CSV включает ID участника и кадровые поля. В новых сохранениях профиль участника заполняется сервером; подразделение и должность на момент сохранения остаются в соответствующей попытке.

## Пароли и восстановление

Пароль — от 10 до 200 символов; хранится только scrypt-хеш с индивидуальной солью. Постоянный пароль недоступен для просмотра. Сброс создаёт новый временный пароль, требует смены и завершает предыдущие сеансы. Смена пароля, блокировка и изменение карточки/прав также делают прежние сеансы недействительными. Собственный пароль меняется в профиле с проверкой текущего. Преподаватель сбрасывает пароли только доступных участников; аккаунты сотрудников управления восстанавливает администратор. Последнего активного администратора нельзя заблокировать или лишить роли.

Если пароль единственного администратора забыт, оператор сервера выполняет внутри контейнера:

```bash
python /app/account_admin.py --login ИМЯ_ЛОГИНА
```

Команда однократно выводит новый временный пароль. Не сохранять его в общем журнале и не включать в переписку с широким доступом. Операция фиксируется в журнале без пароля.

## Совместимость и выпуск

Существующие пользователи, результаты и попытки не объединяются с персональными аккаунтами, не удаляются и не пересчитываются. Для новых участников создаются новые ID; прежний уникальный ключ нормализованного ФИО сохраняется для старых движков. Страницы v2/v3 не изменены.

При включённом режиме WORKBOOK_PERSONAL_ACCOUNTS=1 общие административные входы и прежние административные токены отключены; общий код не открывает новые тетради конструктора. Старые складские и пожарные результаты сохраняют прежний путь доступа через старые движки. Переключение не заменяет отдельного решения о сроках сохранения такого архивного входа.

Перед рабочим выпуском: подтвердить тесты, проверить интерфейсы в браузере, подготовить подразделения и назначения, проверить первоначальный вход администратора и восстановление из резервной копии. Рабочий выпуск не выполняется автоматически из feature-ветки.

Файлы доступа не включаются в образ контейнера. Существующие настройки пожарного доступа остаются в постоянном томе. При отдельном первичном развёртывании зашифрованный пакет доступа устанавливается оператором приватно в каталог данных или по пути WORKBOOK_FIRE_ENVELOPE.
