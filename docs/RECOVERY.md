# Резервное копирование и проверка восстановления

Ежедневная локальная копия создаётся ночью примерно в 03:00 по Красноярску. Задание выполняет systemd на сервере и не зависит от доступности GitHub. Перед включением расписания создаётся первая копия и проверяется восстановление.

В копию входят согласованный снимок SQLite, все файлы данных и изображений, исходники запущенной версии приложения, её настройки окружения и настройки сервера, включая HTTPS. Контрольные суммы проверяются до извлечения. Копия содержит персональные данные и секреты, хранится в закрытом каталоге сервера и не выгружается в GitHub, чат или публичное файловое хранилище.

Каждое задание проверяет архивы, извлекает приложение в новый временный каталог и запускает восстановленную копию в отдельном контейнере без внешней сети и опубликованных портов. Проверяются запуск API, страницы, соответствие результатов базе и доступность скриншотов, если они имеются. Проверочная запись администратора создаётся только в восстановленной копии. После проверки контейнер и временные данные удаляются. Рабочая база не заменяется и не изменяется этой процедурой.

Успешная точка восстановления получает отметку verified.json. При ошибке каталог остаётся с суффиксом .partial и не считается готовой копией. Архивы и настройки имеют закрытые права доступа. При недостатке места задание останавливается без удаления прежних данных.

## Проверка оператором

```bash
systemctl status ifcm-workbooks-backup.timer
journalctl -u ifcm-workbooks-backup.service
systemctl start ifcm-workbooks-backup.service
```

Повторная изолированная проверка конкретной точки:

```bash
python3 /opt/upo-workbooks/maintenance/restore_check.py /opt/upo-workbooks/backups/scheduled/ИМЯ_ТОЧКИ
```

Продуктовые результаты и секреты не должны попадать в журналы проверки. Проверочная команда выводит только статус. Для восстановления на другом сервере потребуются защищённые архивы, Docker и образ, указанный в метаданных, либо восстановление исходников и сборка соответствующей версии. Фактическая замена рабочей базы выполняется оператором отдельной процедурой с остановкой записи и согласованием владельца.

## Что требует решения владельца

Сейчас копии находятся на том же сервере. Для защиты от полной потери сервера необходимо согласовать отдельное защищённое место хранения и права доступа к нему. Независимая внешняя копия пока не настроена.

Сроки хранения копий, ответов и скриншотов должны быть утверждены отдельно. Автоматическое удаление существующих копий и учебных результатов не включено. Также необходимо назначить ответственного за контроль заданий, свободного места и устранение ошибок резервного копирования.

## Согласованные сроки хранения от 29 октября 2026 года

Резервные копии хранятся 14 дней. После успешной проверки новой точки старые
проверенные точки удаляются только из каталога `backups/scheduled`; последняя
исправная точка сохраняется даже при превышении срока. Частичные архивы,
посторонние каталоги и символьные ссылки автоматически не удаляются.

Ответы, заметки с ответами и скриншоты хранятся шесть календарных месяцев от
завершения попытки, а для незавершённых — от последнего сохранения. Для
отправленного пожарного экзамена используется дата отправки. Баллы, номера
попыток, даты, сведения участника и проверки преподавателя сохраняются.
Удалённое содержимое нельзя восстановить сохранением старой вкладки;
участник может начать новую попытку.

Приложение выполняет очистку перед началом приёма запросов и затем каждые
шесть часов. Это применяется также при восстановлении старой копии, чтобы
просроченные ответы не вернулись в работу. `WORKBOOK_RETENTION_ENABLED=0`
отключает обработку только для изолированной диагностики оператором; в
рабочем режиме настройка должна оставаться включённой. Незавершённое
удаление файла повторяется из постоянной очереди.

Предварительный расчёт без изменения данных:

```bash
python /app/retention.py --database /data/workbooks.sqlite3 --data-dir /data
```

Сроки и ответственность согласованы: контроль копирования, доступов,
обновлений, сбоев и восстановления выполняет Владелец продукта. Подключение
внешнего хранилища и VPN остаётся отложенным.
