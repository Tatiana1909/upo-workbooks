# Конструктор рабочих тетрадей — первая версия

Основной учебный каталог: `/v3/index.html`. Конструктор: `/builder/index.html`.
Проверка работ: `/builder/review.html`. Созданные тетради появляются в каталоге v3.
Вход автора в первой версии использует существующую административную учётную запись; отдельные аккаунты преподавателей ещё не добавлены.

## Возможности

- Разделы, текст, картинки, видео (карточка по ссылке или встроенный плеер для прямого MP4/WebM), прямые ссылки на инструкции и отдельные ссылки скачивания.
- Один/несколько правильных вариантов, да/нет, открытые вопросы, практика, заметки.
- Добавление, копирование, удаление, изменение порядка блоков и разделов.
- Автосохранение, контроль конфликтов, копирование тетради, предпросмотр.
- Публикация неизменяемых версий и архивирование из каталога.
- Скриншоты практики: PNG/JPG/WebP, до 5 МБ каждый, 1–10 изображений на задание. Обязательность задаёт автор.
- Проверка по умолчанию для тетради и отдельный режим для каждого задания.
- Автооценка: 10 баллов за верный тестовый ответ или выполненную практику (с обязательным скриншотом при соответствующей настройке).
- Открытые ответы не получают автоматические баллы за сам факт заполнения.
- Преподаватель видит конкретную попытку, ответы и скриншоты, отмечает проверку, ставит 0–100 баллов за задание, оставляет комментарий.
- Итоговые баллы учитывают ручные оценки; комментарии доступны студенту.
- Изменение проверенного ответа/отметки/скриншотов ставит отметку «Требуется повторная проверка» у задания и в списке работ; предыдущий комментарий и баллы сохраняются, но баллы не учитываются до подтверждения проверки. Конфликт при параллельном изменении работы требует её повторного открытия.
- Прогресс заполнения и число ожидающих проверки заданий показываются отдельно: 100% заполнения не означает завершение ручной проверки.

## Хранение и совместимость

Новые таблицы добавляются в существующую SQLite, прежние результаты не преобразуются.
Каждая опубликованная версия получает собственный course_id. Попытки и проверки не смешиваются между версиями.
Скриншоты хранятся на существующем постоянном томе `/data/builder-evidence`; доступ по токену владельца или администратора.
Авторские картинки хранятся в `/data/builder-images` и доступны как учебные материалы.
Перед публикацией версии создаётся SQLite-снимок в `/data/builder-backups`.
Workflow перед обновлением сохраняет код (без `.env`) и SQLite-снимок. При полном резервном копировании тома нужно включать оба каталога изображений.

## Развёртывание

Используется существующий ручной workflow. Развёртывание использует существующий ручной workflow; перед обновлением выполняется резервное копирование.
После согласования: публикация исходников, ручной запуск workflow, проверка health, v3, конструктора, загрузок, ручной проверки и истории.
NIE, его порт и контейнер в коде обновления не используются.

## Проверки

`python -m pytest server/tests -q` — API: права доступа, версии, конфликты, скрытие ключей тестов, скриншоты, обязательность, ручные оценки, новые попытки, совместимость старых курсов.
`node --check builder/*.js` — запускать для каждого JS-файла отдельно.
Проверено локальным Chromium: редактор, предпросмотр, публикация версии, вход студента, сохранение ответов, загрузка скриншотов и их наличие после перезагрузки, ручная проверка и изменение баллов, мобильный экран 390 px без горизонтального переполнения. Карточка видео проверена визуально; встроенный плеер проверяется на локальном тестовом WebM.

## Границы первой версии

Пока используются обычные текстовые поля с переносами строк; визуальный форматированный редактор и таблицы в тексте не добавлены.
Составные вложения кроме картинок и автоматическая проверка содержания скриншотов не реализованы.
Не задан порог успешности и принудительное последовательное прохождение разделов.
Существующие две тетради v3 продолжают использовать прежний движок; их перенос в конструктор требует отдельного импорта.
